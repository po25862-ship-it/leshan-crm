# 樂善 CRM 物件每日同步

這是僅在使用者 Mac 上執行的桌面同步工具，不會把登入密碼或內部編號放進 GitHub。

## 同步流程

1. 從 4 間店、16 種物件類別下載完整 64 份報表；少一份就中止，不寫入 CRM。
2. 依委託書編號去重並下載詳細資料，補上座落、主建物、附屬建物、公設與車位資訊。
3. 讀取已登入後台查詢表的「官網點閱」欄位；有數字超連結才標記官網已上架，沒有超連結就標記未上架。頁面涵蓋率不足 90% 時視為登入失效，整批官網狀態不更新。
4. 後台登入有效時，再以 244 個核對過的林口／上龜山路段與地名做跨店關鍵字查詢。關鍵字命中案名或備註不算數；只收完整詳細頁「座落」可驗證的案件。跨里道路只在 115/09 桃園市門牌資料可唯一對應上龜山里別時納入。報表或詳細頁失敗只略過該筆，不據此判下架。
5. 登入 Firebase，先將現有物件存成同步前 JSON 備份。
6. 以委託書編號精準去重更新；保留人工備註，價格異動另寫歷程。
7. 第一次未出現在完整四店報表只記錄，連續第二次未出現才自動標記「暫時不賣」。人工暫停與已售物件不會被自動改回。
   每筆物件另外保留首次掃描出現、首次掃描未見、首次自動暫時關閉及最近掃描時間；舊物件沒有可靠的歷史首次時間時，從此功能啟用後第一次掃描起算，畫面會註明。
   `syncCoverage: "roadKeyword"` 的跨店路段案件不在四店報表的下架判斷範圍內，也不會因單次路段查詢缺席而被誤標暫時不賣。路段掃描只新增或更新有詳細地址驗證的案件。
8. 產生 18 個工作表的 `物件總表_匯出_YYYY-MM-DD.xlsx`、原始 64 份報表、路段查詢結果、詳細頁與同步紀錄。

## 本機入口

執行 `npm run server` 後開啟 <http://127.0.0.1:8877/>。首次設定會把 CRM 密碼與內部編號存入 macOS 鑰匙圈，並安裝每天 07:30 的 LaunchAgent。CRM 的桌面版「立即同步」按鈕也會開啟這個頁面；手機版不顯示。

每日 07:30 與桌面版「立即同步」都呼叫同一支 `sync.js`，因此都包含路段掃描。若公司後台本月驗證碼尚未更新，四店報表仍可同步，路段掃描會略過並留下紀錄；請在本機入口更新驗證碼後再點「立即同步」。路段範圍見 `road-coverage.txt`；跨里門牌對照使用桃園市 115/09 公開門牌資料的壓縮摘錄 `mixed-road-doorplates-11509.b64`。

## 安全測試

`npm run test:archive` 只讀取測試封存，不會連線或寫入 Firebase。正式寫入必須明確加上 `--apply-crm`，且 64 份來源全部驗證成功。

## 社區與商圈回填

`node backfill-property-locations.js` 只會預覽可由案名、地址與 A7／A8／A9 路段可靠判斷的結果。確認後使用 `node backfill-property-locations.js --apply` 才會先備份現有資料並補入空白欄位；人工已填內容不會被覆蓋。每日同步也會保留並沿用同一套判斷規則。
