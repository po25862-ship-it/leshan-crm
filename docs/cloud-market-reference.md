# CRM 雲端行情與公設

主系統 API 從 Vercel 內的唯讀快照查詢 A7／A8／A9 社區及近兩年度官方買賣，查詢不連接 Mac，也不讀取 Firestore。副系統沿用主系統 API。每次請求先驗證 CRM 登入身分、停用及撤銷狀態；不提供匿名快照下載。

原始市場系統資料仍是更新來源。Mac 的本機發布工作每小時檢查來源版本；有變化才重新加密、提交快照並觸發部署，沒變化就保留現有版本。本機關機或更新失敗時，線上繼續提供最後一次成功的雲端快照。介面顯示雲端同步時間和原始資料發布日期；「更新參考」只重新讀取雲端版本。

## 資料範圍與存放

- 僅匯出社區名稱、門牌配對索引、公設、管理費與官方成交必要欄位；不含客戶、屋主、電傳資料或市場系統連結。
- `api/_data/crm-reference-snapshot.json` 是 AES-256-GCM 加密且壓縮的內容。GitHub 是公開倉庫，不得加入未加密來源資料。
- 解密金鑰只存在 Vercel production 的 Sensitive 設定 `CRM_REFERENCE_SNAPSHOT_KEY` 與本機發布工作的私有設定檔，不得放進前端、Git 或輸出日誌。
- 沿用市場來源既有的本機憑證讀取已發布社區主檔，不把憑證複製到 CRM 或雲端。
- 不新增付費儲存服務。來源版本檢查使用既有服務；仍受既有 Vercel／Google 帳戶方案與用量限制。

## 發布程式

`scripts/publish_market_snapshot.py --source-root <市場系統資料夾> --key-file <私有金鑰檔>` 產出快照。加上 `--push` 時，只在獨立發布用 checkout 更新快照檔、提交並推送 main。未取得完整來源、版本變動中、推送失敗均保留最後成功部署，不強制推送。

來源更新不等於雲端已更新。查核：本機工作日誌 → GitHub 快照提交 → Vercel production Ready → CRM 的雲端最後同步時間。金鑰遺失時須重新產生金鑰、更新 Vercel 設定並重建快照；不得只更換其中一端。
